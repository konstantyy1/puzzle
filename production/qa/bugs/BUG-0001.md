# Bug Report

## Summary
**Title**: Online fights used an outdated picture list instead of the current gallery
**ID**: BUG-0001
**Severity**: S4-Low
**Priority**: P2-Fix soon
**Status**: Closed
**Reported**: 2026-11-09
**Reporter**: —

## Classification
- **Category**: Network
- **System**: Arena — server match setup (`newMatch` in `api/arena.js`)
- **Frequency**: Always
- **Regression**: Yes — the server copy of the list was not updated when the gallery changed in v12

## Environment
- **Build**: main `5d60782` (client v21); fixed in `fac6b7b`
- **Platform**: Server (Vercel functions); affects every client
- **Scene/Level**: Arena → online fight (ranked or casual, including server bot opponents)
- **Game State**: Any match created by the server

## Reproduction Steps
**Preconditions**: A checkout of the build above

1. Compare `PIDS` in `api/arena.js` (line 8) with `DATA.GALLERY` (built in `v12/data.js`, line 33).
2. Run `npm test` and check the test "online fights use the same pictures as the gallery" in `tests/unit/data.test.mjs`.
3. Start an online fight and note the picture id (`pid`) in the match the server returns.

**Expected Result**: Online fights use the same 31 pictures as the in-game gallery.
**Actual Result**: 12 of the 31 server ids came from the gallery before v12, so some online fights used pictures that are no longer in the gallery.

## Technical Context
- **Likely affected files**: `api/arena.js` (`PIDS`, line 8; read by `newMatch`)
- **Related systems**: Gallery data (`DATA.GALLERY`, `v12/data.js`); free play and offline bot fights already used the gallery
- **Possible root cause**: The server keeps its own copy of the picture list, and that copy was not updated together with the client gallery

## Evidence
- **Logs**: Before the fix, `npm test` failed with `ERR_ASSERTION` (`deepStrictEqual`) in `tests/unit/data.test.mjs`; after the fix all 44 tests pass
- **Visual**: None needed — every old id was still a valid picture, so nothing looked broken

## Notes
No player-visible breakage: both players in a match always received the same valid `pid` from the server. The parity test in `tests/unit/data.test.mjs` now keeps the two lists in sync.
