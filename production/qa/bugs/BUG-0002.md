# Bug Report

## Summary
**Title**: Online PvP trusts each player's own reported hits without a server-side plausibility check
**ID**: BUG-0002
**Severity**: S3-Medium
**Priority**: P3-Backlog
**Status**: Open
**Reported**: 2026-11-09
**Reporter**: —

## Classification
- **Category**: Network
- **System**: Arena PvP live moves (`act` and `decide` in `api/arena.js`)
- **Frequency**: Always — this is how the current fight protocol works
- **Regression**: No (current protocol design)

## Environment
- **Build**: main `fac6b7b` (client v21)
- **Platform**: Server (Vercel functions); any client
- **Scene/Level**: Arena → online fight between two real players
- **Game State**: Ranked fight in progress

## Reproduction Steps
**Preconditions**: Code review of the build above (no live attempt was made)

1. Read `act` and `clean()` in `api/arena.js`: the server stores the damage and the "finished" flag that each client reports, after only capping them (for example, damage at most 1500).
2. Read `decide`: the winner and the rating change are computed from those stored client reports.
3. Note that nothing compares the reports with the fight timeline (start time `t0`, grid size, time passed).

**Expected Result**: The server only accepts fight results that are possible for the time that has passed.
**Actual Result**: Any capped value is accepted, so a modified client could end a ranked fight early and gain rating.

## Technical Context
- **Likely affected files**: `api/arena.js` (`act`, `clean`, `decide`)
- **Related systems**: Arena client (`v20/arena.js`); rating and seasons (`lb:rt`, `lb:s:<YYYY-MM>`)
- **Possible root cause**: Each client computes its own hits and the server only relays and stores the reports; there is no server-side plausibility rule

## Notes
- Needs a product decision before any change: a strict time rule (for example, a minimum time per placed piece) could reject genuinely fast players.
- Options: a plausibility rule based on time passed and grid size; flagging outliers for review instead of rejecting them; server-side checks of placed pieces.
- Accepted risk for bot fights (`end`): the result comes from the client, but a win counts only after at least 12 s, only once per match, and with half the rating step (K=16 instead of 32).
- Nothing was changed in this round, so online fights work exactly as before.
